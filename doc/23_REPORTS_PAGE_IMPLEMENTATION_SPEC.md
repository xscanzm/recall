# 23. 报告页施工规格

本文档定义报告页。报告页是 Recall 的直接价值出口，必须清楚、可编辑、可复制。

## 1. 页面目标

报告页回答：

- 我今天可以给自己看什么？
- 我今天可以提交什么？
- 本周/月可以怎么总结？
- 历史报告在哪里？

## 2. 布局

```text
左侧导航 | 报告主区域 | 右侧来源/设置面板 optional
```

主区域宽度最大 920px，居中或左对齐。

顶部：

```text
报告
把每天的记录整理成复盘、日报、周报和月报。
```

Tabs：

- 我的复盘
- 工作日报
- 周报
- 月报
- 历史

## 3. 我的复盘 Tab

### 3.1 用途

给用户自己看。真实、温和、帮助回忆和清空大脑。

### 3.2 UI

顶部操作：

- 日期选择。
- `生成我的复盘`
- 如果已生成：`重新生成`、`复制`、`编辑`

内容结构：

```text
今天主要在做什么
有价值的进展
还没收尾的事
值得以后记住
明天可以从这里继续
```

每个条目右侧提供：

- 查看来源
- 删除此条

## 4. 工作日报 Tab

### 4.1 用途

给上司、团队、客户或协作者看。

### 4.2 生成入口

如果今天没有工作日报：

显示：

```text
还没有工作日报。
先选择今天适合汇报的工作片段，再生成一份可复制的日报。
```

按钮：

- `选择片段生成日报`

点击后跳到今日页的工作日报选择模式，或在报告页内打开选择面板。

### 4.3 工作日报正文

结构固定：

```text
今日完成
项目进展
问题与风险
明日计划
```

右上角按钮：

- 复制
- 编辑
- 重新选择片段
- 导出 Markdown

### 4.4 风格切换

提供 3 个选项：

- 简洁
- 标准
- 稍正式

默认：标准。

不要提供十几个语气选项。

## 5. 周报 Tab

### 5.1 数据来源

周报优先基于：

- 本周已确认的工作日报。
- 本周 TimelineBlocks 中 reportable=true 的内容。
- 项目进展。
- 完成/未完成任务。

### 5.2 结构

```text
本周概览
项目进展
完成事项
关键决策
风险与阻塞
下周计划
```

### 5.3 UI

顶部：

- 周选择。
- 生成周报。
- 复制。
- 编辑。

## 6. 月报 Tab

月报结构：

```text
本月概览
主要项目
关键成果
重要决策
持续风险
下月重点
```

月报可以后置，但页面结构应保留。

## 7. 历史 Tab

列表字段：

- 日期/周期。
- 报告类型。
- 标题。
- 更新时间。
- 操作：查看、复制、删除。

过滤：

- 类型。
- 日期范围。
- 项目。

## 8. 编辑器

报告编辑器要求：

- 普通 textarea 或富文本编辑器均可。
- 必须支持复制 plain text。
- 不要只显示 JSON。
- 编辑后保存到 reports。

## 9. 来源面板

点击“查看来源”时，右侧或弹层显示：

- 相关 timeline block 标题。
- 时间范围。
- 摘要。
- 来源事实。

不要默认显示截图。

## 10. 验收

通过标准：

- 我的复盘和工作日报是两个不同入口。
- 工作日报必须来自用户选择片段。
- 工作日报可复制。
- 报告正文不是 JSON。
- 历史报告可查看。
- 周报/月报有页面入口。
