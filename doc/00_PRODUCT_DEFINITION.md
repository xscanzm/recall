# 00. Product Definition

## 产品名

中文名：回声  
英文名：Recall

## 产品定义

回声 Recall 是一个基于视觉模型和大语言模型的主动型桌面上下文助理。它获得用户授权后，观察用户在电脑前的工作活动，把原本会自然流失的上下文转化为结构化记忆、任务追踪、项目进展、提醒、日报、周报和复盘。

Recall 不是为了记录屏幕本身，而是为了给用户的电脑活动赋予价值。

## 核心价值链

```text
捕获 Capture
  -> 看见 Observe
  -> 理解 Understand
  -> 结构化 Structure
  -> 关联 Link
  -> 主动帮助 Act
```

截图、窗口标题、应用名、URL、时间、用户活动信号都是输入。真正长期沉淀的是：

- 任务
- 决策
- 项目进展
- 人物信息
- 用户偏好
- 知识片段
- 风险和阻塞
- 日报、周报、复盘
- 可解释的主动提醒

## 目标用户

MVP 优先服务高上下文知识工作者：

- 创业者
- 产品负责人
- 独立开发者
- 研究员
- 内容创作者
- 咨询顾问
- 投研/分析类用户

他们的共同特征：

- 长时间在电脑前工作。
- 频繁切换网页、文档、聊天、代码、表格、设计稿。
- 很多关键想法、任务和判断散落在工作过程中。
- 愿意配置 API Key。
- 能接受早期产品不完美，但要求产品真正有用。
- 关心隐私，不接受监控感。

## 产品人格

Recall 应该像一个安静但主动的工作助理：

- 平时安静观察和整理。
- 不轻易打断用户。
- 到了合适时间，主动给出提醒和总结。
- 每个提醒都能解释原因。
- 用户纠正后，它应该越来越懂用户。

不要做成：

- 监控软件
- 截图历史工具
- 屏幕录制工具
- 聊天机器人壳
- 机械流水账
- 普通笔记软件

## 核心原则

### 1. 模型是系统大脑

规则只负责安全、边界、节流、存储和 UI 状态。真正的观察、抽取、关联、判断、报告生成，必须由视觉模型和 LLM 通过结构化协议完成。

### 2. 截图是输入，不是资产

截图用于视觉模型理解，可以按用户配置本地短期保留。默认保留当天，可配置为数小时到 7 天。截图不上传到 Recall 自有服务器，不作为主界面内容，不做截图墙。

### 3. 记忆自动生长

L0 到 L3 都由模型自动生成。用户不需要逐条确认后系统才记忆。用户通过编辑、删除、合并、纠错来修剪记忆。

### 4. 主动但不冒犯

默认主动生成应用内提醒、待确认事项、日报和周报。桌面通知必须用户手动开启。禁止默认自动外发报告或替用户承诺。

### 5. 优先不漏，随后压缩

第一版采集策略优先覆盖真实工作活动。因为 flash 类视觉模型成本低，不应把 API 预算作为主限制。需要通过模型压缩、去重、分层记忆和本地保留策略控制信息量。

### 6. 每条智能输出可追溯

任务、决策、提醒、日报中的关键内容必须能追溯到 source observation、fact 或 scene。UI 中至少要能展示“为什么这么判断”。

## 成功标准

Alpha 成功不是功能数量，而是用户感知：

- 用户每天结束时愿意打开 Recall 看今天。
- 用户认为 Recall 记住了自己没来得及记的东西。
- 用户能从 Recall 找回昨天或上周的工作上下文。
- 用户愿意复制 Recall 生成的日报/周报。
- 用户愿意修正 Recall 的错误，因为修正后它更好用。

建议 Alpha 指标：

- 5-10 个种子用户。
- 至少 3 人连续使用 7 天。
- 每人每天产生 30 条以上 L1 facts 或 5 个以上 L2 scenes。
- 每人每天至少查看一次今日汇总。
- 每周至少复制或编辑一次周报。
- 用户主动搜索或追问历史记忆。

## 非目标

MVP 不做：

- 多端同步。
- 云端托管用户屏幕历史。
- 团队管理和员工监控。
- 自动外发日报/周报。
- 本地小模型。
- 通用 RPA 自动执行。
- 复杂知识图谱大画布。
- 截图回放播放器。
- 以聊天作为唯一主界面。
