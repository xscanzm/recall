# 01. MVP Scope

## MVP 目标

第一版要验证一件事：

> Recall 能否自动理解用户今天在电脑前做了什么，并把它整理成任务、项目进展、决策、提醒和日报。

MVP 不追求漂亮地覆盖所有高级功能，先把自动观察、模型 pipeline、记忆分层、应用内提醒和日报闭环跑通。

## 必须实现

### 桌面应用

- Windows-first。
- Electron + React + TypeScript。
- 后台常驻能力。
- 托盘入口。
- 明显的观察状态：观察中、暂停、黑名单跳过、模型错误。

### 模型配置

- 视觉模型配置。
- 语言模型配置。
- 两者分开 endpoint/key/model。
- 第一版采用 OpenAI-compatible API。
- API Key 存系统安全存储，不进 SQLite。
- 提供连接测试。

### 活动窗口观察

- 只观察活动窗口。
- 使用鼠标/键盘活动、窗口切换、标题变化、内容变化和场景边界触发采集。
- 不采集黑名单应用。
- 不采集明显敏感场景。
- 支持截图本地短期缓存。

### 截图保留

- 默认：保留当天，次日自动删除。
- 用户可配置：立即删除、1 小时、6 小时、当天、3 天、7 天。
- 截图文件只存本地 app data/cache 目录。
- UI 不展示截图墙。
- 每条 observation 记录截图 retention 状态和本地路径是否存在。
- 删除过期截图不影响结构化记忆。

### AI Pipeline

必须实现 5 个 AI workers：

- Observer：视觉观察员。
- Extractor：事实提取员。
- Linker：记忆关联员。
- Judge：主动性判断员。
- Reporter：日报/周报生成员。

每个 worker 必须使用 JSON schema 校验输出。

### 记忆系统

必须实现：

- L0 Observation
- L1 Fact
- L2 Scene
- L3 Memory Object

L0-L3 全部自动生成。用户可在 UI 中编辑、删除、合并和纠错。

### 主动提醒

MVP 提醒默认只在应用内：

- 待确认事实。
- 疑似未完成任务。
- 今日重要进展。
- 今日关键决策。
- 明日接续建议。

桌面通知必须设置中手动开启。

### 日报和周报

- 每日固定时间自动生成日报草稿。
- 用户可手动重新生成。
- 周报可在周末或用户点击时生成。
- 报告必须基于 L1/L2/L3，不直接基于截图。
- 报告内容可编辑、复制。

### UI 页面

MVP 页面：

- 今日
- 提醒
- 任务
- 项目
- 报告
- 记忆库
- 设置
- 信任中心

### 本地搜索

- 搜索 tasks、facts、scenes、projects、reports。
- 搜索结果显示来源、时间、项目和相关提醒。

## 可以延后

- 多端同步。
- 云备份。
- 本地小模型。
- 插件系统。
- 浏览器扩展。
- 深度日历集成。
- 自动发送邮件或消息。
- 团队协作。
- 复杂可视化图谱。
- 语音输入。

## 禁止在 MVP 中做

- 默认上传截图到 Recall 自有服务器。
- 默认展示截图历史墙。
- 默认桌面弹窗频繁提醒。
- 自动对外发送日报。
- 自动修改用户文件。
- 把网页或文档里的提示词当系统指令执行。
- 把低可信推测伪装成确定事实。

## MVP 成功体验

完成一天工作后，用户打开 Recall，应看到：

- 今天主要做了哪几件事。
- 哪些项目有进展。
- 哪些任务可能还没收尾。
- 今天做过哪些决策。
- 明天建议从哪里继续。
- 一份可以编辑/复制的日报。

如果做不到这个，哪怕捕获、数据库、页面都完成，也不能算 MVP 成功。
