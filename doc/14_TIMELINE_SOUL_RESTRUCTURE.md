# 14. Timeline Soul Restructure (回声 Recall 时间轴灵魂重构方案)

在桌面助理类产品中，“时间轴（Timeline）”是一个极其经典但又极度危险的设计。

## 🛑 经典误区：把时间轴做成“数字监工考勤表”

如果产品经理用简单的工程师思维来做“半小时时间轴”，界面往往会变成这样：
*   **14:00 - 14:30**：使用 VS Code 45%，使用 Chrome 55%（停留于 stackoverflow.com）
*   **14:30 - 15:00**：使用 WeChat 80%，使用 Chrome 20%
*   **15:00 - 15:30**：电脑无活动（闲置）

**这样的时间轴是反人性的：**
1.  **放大焦虑**：用户只要一看到自己“摸鱼”或“闲置”的时间，就会产生负罪感。
2.  **监控感极强**：这不像是一个助理，更像是一个坐在你身后、每隔半小时就在本子上划拉你干了什么的班主任。
3.  **信息密度极低**：堆砌了应用的名称和无意义的百分比，用户无法从中获得任何对工作实质有帮助的“心流闪光点”。

## 🍃 灵魂重构：“时光脉络（Chronos Aura）”与“心流呼吸”

我们决定重构这个半小时时间轴。**我们依然以“每半小时”为基本的时间刻度与逻辑聚类边界，但是在呈现给用户时，我们用“心流与陪伴”的逻辑彻底换掉它。**

我们叫它：**“时光脉络”**。

```text
  (开始记录)
     │
     o  09:00 - 09:30   【沉思起航】 ☕
     │                  “在寂静中，你点亮了屏幕，整理了今天的 3 个设计想法。
     │                   这是一个安静、有条不紊的早晨。”
     │
     o  09:30 - 10:30   【深水沉浸】 🌊 (合并高能区间)
     │                  “你连续 1 个小时几乎没有触碰其他干扰软件，
     │                   一心扑在重构的全局核心逻辑上。”
     │
     o  10:30 - 11:00   【断奏 / 微歇】 🍃
     │                  “你让键盘稍作休息。或许是一杯咖啡的时间，
     │                   或者是站起来伸了个懒腰。”
     │
     o  11:00 - 11:30   【灵感碰撞】 ⚡
     │                  “你在群里和小明连续抛出了 5 句关于配色的奇思妙想。
     │                   火花正在这里发生。”
```

## 🛠️ 三大动态重塑机制（AI 驱动）

### 1. 动态语义命名：干掉机械的“时间分段”
*   大模型（Observer & Extractor）在处理每 30 分钟的 context 时，**严禁使用格式化的技术标题**。
*   AI 必须根据用户这半小时内的**核心状态与心智活动**，动态拟定一个具有诗意和工作属性的“心流标签”。
    *   *如果一直在敲代码*：**「深水沉浸」**（Deep Diving）
    *   *如果频繁切换网页查资料*：**「灵感搜寻」**（Questing）
    *   *如果在微信/Slack快速打字*：**「共识碰撞」**（Sparking）
    *   *如果中途去喝水或没动静*：**「留白呼吸」**（Breathtaking）（**我们不叫“闲置”或“摸鱼”，我们叫“给大脑充充电、稍作休息”，彻底消灭负罪感**）

### 2. 呼吸弹性聚合：打破死板的“切片僵化”
*   如果用户连续两小时都在极度专注地写同一个文档，界面如果显示 4 个一模一样的“半小时切片”，会显得极其繁琐。
*   **AI 弹性合并**：当发现连续的半小时切片处于“高关联的心流状态”下，时间轴会自动发生**柔和的坍缩与聚合**，将其编织成一个大块的 **「深水专注区间」**。而当心流发生切换（如从写代码突然转为查快递或闲聊）时，时间轴再敏锐地分裂出新的“灵感足迹节点”。
