# 02. User Flows

## Flow 1: 首次启动

1. 用户打开 Recall。
2. 显示欢迎页，说明三件事：
   - Recall 会理解桌面上下文，帮助形成记忆和报告。
   - 截图只作为模型输入，本地短期保留，可配置。
   - 用户自带模型 API Key，视觉模型和语言模型分开配置。
3. 用户进入模型配置。
4. 用户填写视觉模型 endpoint、model、api key。
5. 用户填写语言模型 endpoint、model、api key。
6. 用户点击测试连接。
7. 测试通过后进入隐私设置。
8. 用户确认默认黑名单应用和截图保留策略。
9. 用户点击“开始观察”。

失败处理：

- 模型连接失败：显示 endpoint/model/key 可能问题，不显示完整 key。
- 权限失败：说明需要屏幕捕获权限或窗口捕获能力。
- 用户跳过配置：进入只读空状态，不能开始观察。

## Flow 2: 开始观察

1. 用户点击“开始观察”。
2. 托盘和主界面状态变为“观察中”。
3. 系统监听活动窗口、标题、用户输入、内容变化。
4. 捕获服务生成 capture bundle。
5. Observer 视觉模型生成 L0 observation。
6. Extractor 生成 L1 facts。
7. Linker 把 facts 关联到项目、任务、人物、决策。
8. Judge 判断是否生成应用内提醒。
9. UI 中今日页逐步出现工作主线、线索、提醒。

用户必须始终能看到当前状态：

- 观察中
- 已暂停
- 黑名单跳过
- 敏感内容跳过
- 模型错误
- 正在整理

## Flow 3: 暂停和恢复

入口：

- 托盘菜单。
- 主界面顶部状态按钮。
- 快捷键可后续支持，MVP 可不做。

暂停后：

- 不截图。
- 不调用模型。
- 不新增 observation。
- 今日页显示暂停期间不会记录。

恢复后：

- 继续监听活动窗口。
- 不补采暂停期间内容。

## Flow 4: 忘掉最近

用户可以点击：

- 忘掉最近 15 分钟
- 忘掉最近 30 分钟
- 忘掉最近 1 小时
- 忘掉今天

执行逻辑：

1. 删除对应时间范围内截图缓存。
2. 删除对应 observation。
3. 删除或标记从这些 observation 生成的 facts/scenes。
4. 对 L3 objects 做反向影响：
   - 如果 L3 只由被删除 facts 支撑，删除或标记失效。
   - 如果 L3 还有其他来源，移除 source link 并重新计算摘要。
5. 报告若引用被删除 facts，标记需要重新生成。

## Flow 5: 应用内提醒

提醒来源：

- Judge worker 输出 proactive_items。
- Reporter 生成日报时发现未完成事项。
- Linker 发现历史任务被再次提到但没有完成证据。

提醒位置：

- 今日页右侧提醒栏。
- 提醒页。
- 日报草稿中的“需要关注”区域。

提醒必须包含：

- 标题。
- 简短原因。
- 来源事实数量。
- 置信度或确定性标签。
- 操作：确认、忽略、稍后、标记完成、编辑、不要再提醒类似内容。

默认不弹桌面通知。桌面通知只在设置中开启后使用。

## Flow 6: 用户纠错

用户可以对任何事实、任务、场景、项目归属、日报条目纠错。

纠错类型：

- 内容错了。
- 不重要。
- 项目归属错了。
- 这个任务已完成。
- 这不是任务。
- 不要记这类内容。
- 这是敏感内容，删除。

系统处理：

- 保存 edit history。
- 更新对应对象。
- 把纠错写入 user_feedback。
- 后续 Judge 和 Linker 调用时带入用户反馈摘要。

## Flow 7: 日报生成

触发：

- 每天固定时间，例如 18:30。
- 用户手动点击“生成今日报告”。

输入：

- 今日 L2 scenes。
- 今日 tasks。
- 今日 decisions。
- 今日 project progress。
- 今日 unresolved reminders。
- 用户偏好和日报格式设置。

输出：

- 今日标题。
- 项目进展。
- 完成事项。
- 未完成事项。
- 关键决策。
- 风险/阻塞。
- 明日建议。
- 待确认项。

用户操作：

- 编辑。
- 复制。
- 重新生成。
- 标记某条不准确。
- 从日报条目跳转到来源记忆。

## Flow 8: 周报生成

触发：

- 用户手动点击。
- 设置中开启每周固定时间生成。

输入：

- 本周 daily reports。
- 本周 L2 scenes。
- 本周 project progress。
- 本周 completed/open tasks。
- 本周 decisions。

输出：

- 本周概览。
- 按项目分组的进展。
- 完成事项。
- 关键决策。
- 风险和阻塞。
- 下周建议。

## Flow 9: 历史查询

用户搜索或询问：

- “我昨天关于 Recall 定了什么？”
- “上周还有哪些没完成？”
- “某个项目最近进展是什么？”

第一版可以做轻量问答：

- 输入自然语言。
- 检索相关 facts/scenes/reports。
- LLM 基于检索结果回答。
- 回答必须列出来源对象。

不要把聊天作为主界面。聊天只是查询入口。
