feat: 报告信息图 + 月报独立契约 + 生成通知 + 调度器始终执行 + 活动窗口化 (v0.4.2)

本次版本聚焦「报告呈现与触达」：把文字报告升级为「文字 + 信息图 + 桌面提醒」的完整闭环，月报从周报复用模式独立为自有契约，调度器不再受 autoGenerate 门控始终按设定时间自动生成，今日活动节奏图从固定 0-24h 时钟映射改为实际观察时段映射。

## 1. 报告信息图生成（Infographic Generation）

- 新增 InfographicService：每份正式报告（个人复盘/工作日报/周报/月报）落库后异步生成 16:9 中文信息图，嵌入报告正文上方，可下载
- 图片保存到 userData/report-images/<reportId>.{png|jpg|jpeg|webp}，20MB 上限，180s 超时，fire-and-forget 失败不影响正文
- 新增 Cloudflare Worker 端点 POST /api/infographic/generate：作为图像服务密钥代理，上游模型 sensenova-u1-fast，尺寸 2752x1536，按 CF-Connecting-IP 限流 100 次/天
- 新增 IPC 通道 reports:getImage + 推送通道 reports:imageReady
- Prompt 构造：基于 VisualBrief + 5 套视觉方向 + 5 套内容风格 + 6 类主视觉隐喻
- 隐私安全：cleanVisualText 主动剥离 sourceFactIds/sourceSceneIds/URL/Bearer/sk-xxx 等敏感字段，只把"短事实卡片"传给图像模型
- 生命周期联动：报告编辑/删除/级联标 stale/清空数据时同步删除信息图；ReportRepository.normalizeReportContentId 保证 report.id 稳定
- 渲染层：ReportInfographic 组件挂在 5 个 Tab 的 report-article 顶部，含下载按钮

## 2. 月报独立契约（Monthly Report Contract）

- 月报从「复用 weekly 生成逻辑后改 type」升级为独立的自然月生成流程
- 新增 schema MonthlyReportOutputSchema：omit weekStart/weekEnd/nextWeekSuggestions 后 extend monthStart/monthEnd/nextMonthSuggestions；normalizeMonthlyReportOutput 兼容 weekly 字段名
- 新增 ReporterWorker.generateMonthlyReport(monthKey, requirement)：getCalendarMonthRange 计算自然月首末日（兼容闰年 2 月 29 日），最多拉取 31 条 daily reports
- 新增 buildMonthlyPrompt：明确要求"必须覆盖完整自然月"、"禁止把周期写成'本周/周报/下周'"
- 新增 ReportScheduler.generateMonthlyReportNow：月报没有独立自动调度状态，不污染周报状态字段
- IPC handlers 重写：reports:generate 的 monthly 分支直接调用 generateMonthlyReportNow(dateKey.slice(0,7))
- 渲染层：ReportEditor 新增 MonthlyReportContent 类型 + isMonthlyContent() 判定 + formatReportAsText 月报分支

## 3. 报告生成通知与未读提醒（Report Notifications）

- 新增事件类型 ReportGeneratedEvent：{reportId, type, title, dateKey}
- 新增推送通道 reports:generated：三个 Writer 在 reportRepo.create 成功后调用 onReportGenerated 回调
- 新增 IPC 通道：reports:notification:get / dismiss / open
- 启动期事件缓冲：pendingReportGeneratedEvents 与 pendingReportNotifications 队列，确保主进程在 renderer 加载完成前生成的事件不丢失
- 桌面卡片：复用 EndOfDayReviewService 的独立 BrowserWindow，新增 showReportNotification/dismissReportNotification/openReportNotification
- 新增 ReportGeneratedPopup 组件：25 秒自动消失进度条，鼠标悬停暂停计时
- 顶栏 Bell 角标：AppShell 显示「有新的未读报告（N）」，点击跳转报告页并清除未读
- 状态层持久化：store.ts 的 unreadReports 通过 localStorage["recall.unread-reports.v1"] 持久化，最多 50 条；相同 reportId 重复推送只保留最新

## 4. 调度器始终自动执行 + 设置页增强

- 行为变更：日报与个人复盘不再受 autoGenerate 开关门控，始终按设定时间自动生成；autoGenerate 字段降级为「兼容旧设置」
- 时间源统一：日报时间优先取 settings.notification.dailyReportTime，回退到 settings.dailyReport.time
- 类型兼容：isDailyReportDone 同时检查 daily 和 work_daily_report 两种 type
- 互斥保护：checkSchedule 与 checkMissedSchedules 之间通过 isChecking/isBackfilling 互斥
- 周报触发日变更：从「每周日」改为「每周五」
- 设置页新增：个人复盘时间 time picker，默认 22:00
- 失败重试：历史失败日补跑的指数退避策略

## 5. 今日活动窗口化与节奏图重构

- 节奏图从「固定 0-24h 时钟映射」改为「实际观察时段映射」
- 新增数据结构 TodayActivityWindow：合并后的窗口含 id、sourceEpisodeIds、合并后的 summary/categoryConfidence/projectNames/topicTexts
- 合并规则 mergeActivityWindows：相邻 Episode 满足 ① 同 category ② 间隔 ≤ 5 分钟 ③ 若双方都有 projectName 则需至少一个相同，才合并
- 观察时段 observedStartAt/observedEndAt：取所有 observation interval 的最早 startMs 和最晚 endMs
- 新增映射函数 timeToRoutePercent：线性映射到 0-100% 路径位置，替代旧的 clockMinutesToRoutePercent
- 动态时间标签 buildRhythmTimeMarkers：根据观察时长自适应步长（≤45min→5min、≤150min→15min、≤360min→30min、≤720min→60min、更长→120min）
- 点击交互：onOpenWindow 替代 onOpenEpisode，TodayPage.handleOpenWindow 通过 sourceEpisodeIds 反查时间轴 block
